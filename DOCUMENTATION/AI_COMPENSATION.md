# Задача №12: компенсация нелинейности измерения угла — анализ данных

Проверка по реальному файлу `DATA/MEASURE/MEASURE.json` (100 точек, i0…i99) и
алгоритма из `DOCUMENTATION/AI_POLINOME_CALIB.md` (Задача №9). Все величины
посчитаны **формулами пайплайна** (`make_point`, раскладка ph↔s, `ADC_MAX=3500`):

    b_i = max(0, 3500 − s_i),   P = Σ b_i
    Dx = (b4 + b3 − b1 − b2) / P     # право − лево
    Dy = (b1 + b4 − b2 − b3) / P     # верх − низ
    u  = erfinv(clip(D, ±0.95))      # базис фита (нож-модель почти линейна по u)

Фит — МНК по осям отдельно; честная ошибка — leave-one-out RMSE (точная
hat-матрица) и hold-out 70/30 (200 разбиений). Базис, фильтрация и схема — как в
§11 `AI_POLINOME_CALIB.md`; здесь только проверка на фактических данных.

## 12.0. Краткий вывод

| Вопрос | Ответ |
|---|---|
| 1. Полином 3-й степени строится? | **Да**, но честный оптимум — степень **2** (deg3 нужен только по оси x на очищенных данных; deg4 уже переобучается). |
| 2. Данные консистентны? | **В целом да** (центр повторяется до 0.008 D ≈ 0.02°), но есть ~5 выбросов (опечатки ввода угла + 1 перепутанная точка `i60`); ось **y заметно шумнее** x. |
| 3. Точек достаточно? | **Да, с запасом** — 100 при нужных 30 для deg3; покрытие 2-D хорошее (52 точки вне осей). Узкое место — не число точек, а шум одного кадра. |
| 4. Компенсацию можно проверить? | **Да, проверено.** Полином снижает ошибку угла ≈вдвое против нож-модели (x: 0.18°→0.08°, y: 0.21°→0.14°; по x на чистых данных до **0.04°**). |

**Главный практический итог:** компенсация работает и оправдана, но рекомендуемая
степень — **2 (макс. 3 по x)**, с обязательной отбраковкой выбросов; перекрёстные
члены не нужны (оси датчика почти не повёрнуты к осям столика — достаточно двух
1-D полиномов `θx(ux)`, `θy(uy)`).

## 12.1. Что показывают сами данные

- **Диапазон.** `Dx ∈ [−0.812, +0.621]`, `Dy ∈ [−0.668, +0.678]`. **Ни одна
  точка не в насыщении**: `|D|>0.95` — 0 точек, `|D|>0.90` — 0. Клампинг `b=0`
  (отсчёт ≥ 3500) не сработал ни разу. Значит фильтр по насыщению из §11.3
  ничего не выкинет — весь набор внутри зоны линеаризации.
- **Углы столика.** x: до ±2° (одна точка −2.66°), y: ±2°. Шаг столика ≈ **1/6°**
  (0.16, 0.33, 0.5, 0.66, 0.83, 1.0 …, кратно 0.1667). Усечение 1/6 → «0.16»
  само по себе вносит метку с погрешностью ~0.005–0.01°.
- **Покрытие 2-D.** 98/100 точек в рабочей зоне `|θ|≤2°`; **52 точки вне осей**
  (`|θx|>0.3 и |θy|>0.3`), `std(angle_y)=1.04`. Это **не** вырожденный «стенд
  качает только x» — перекрёстные члены в принципе определимы (обусловленность
  матрицы плана deg3 `cond=34.9`).

## 12.2. Вопрос 1 — можно ли построить полином 3 степени

Да. Формальных препятствий нет:

- 10 коэффициентов/ось при 100 точках — запас **×10** (норма §11.2 — ×3);
- `cond(V)`: deg2 → 10, deg3 → 35, deg4 → 136 (deg3 ещё уверенно устойчив);
- базис `u = erfinv(D)` корректен — нож-модель почти линейна по `u`, поэтому уже
  degree 1–2 ловит основное.

Но **кросс-валидация говорит, что 3-я степень избыточна** (LOO RMSE, градусы):

| степень | k/ось | LOO_x (все) | LOO_y (все) | LOO_x (без 5 выбросов) | LOO_y (без выбросов) |
|---|---|---|---|---|---|
| 1 | 3  | 0.099 | 0.142 | 0.074 | 0.131 |
| 2 | 6  | **0.084** | 0.134 | 0.051 | 0.126 |
| 3 | 10 | 0.086 | 0.134 | **0.039** | 0.126 |
| 4 | 15 | 0.088 | 0.132 | 0.036 | 0.127 |

Чтение таблицы:
- **На полном наборе** deg3 НЕ лучше deg2 (LOO_x 0.084→0.086, LOO_y 0.134→0.134) —
  упёрлись в шум/выбросы, а deg4 по x уже переобучается (LOO_x растёт).
- **После удаления 5 выбросов** (см. §12.3) по оси **x** степень 3 реально
  помогает: `0.051 → 0.039°`. По оси **y** — плато `≈0.126°` при любой степени:
  это шумовой потолок y-данных, моделью его не опустить.
- **Перекрёстные члены пользы не дают.** Сепарабельный deg3 (только чистые
  степени `ux`, `uy`): LOO_x=0.085, LOO_y=0.133 — практически равно полному deg3
  (0.086 / 0.134). Вывод: оси датчика почти не повёрнуты относительно осей
  столика, связи `Dx↔θy` нет → **достаточно двух одномерных полиномов**.

**Рекомендация:** степень по умолчанию **2**; **3 — только по оси x** и только на
очищенных данных; degree 4 запретить (оверфит). Выбор степени — по LOO, не на глаз.

## 12.3. Вопрос 2 — консистентность данных

Достаточная, но с конкретными дефектами:

**Хорошо:**
- Центр `(0,0)` снят трижды (`i0, i52, i81`): разброс `Dx=0.0079`, `Dy=0.0017`
  → ≈ **0.02°**. Отличная повторяемость, опорная точка надёжна.

**Проблемы (всего ~5 точек из 100, 5%):**
- **Перепутанная подпись `i60`.** Дубль `(0.5, 1.0)` снят дважды: `i54` и `i60`,
  но они расходятся на `ΔDx=0.22`. Проверка по соседям столбца x=0.5
  (`i53/i55/i56`: Dx=0.13/0.09/0.08): `i54` (Dx=0.101) согласуется, `i60`
  (Dx=0.323) — нет. **`i60` — ошибочная метка** (реальный угол ≈ x:1.0–1.2), его
  надо выкинуть. `i60` — крупнейший выброс по обеим осям.
- **Опечатки ввода угла** на сетке 1/6°: `i17 = 1.2` (вне сетки, должно быть
  ~1.16/1.33), `i37–i39 = 0.3` (вместо 0.33), `i97 = −0.67` (вместо −0.66).
- **Глитч кадра `i29`:** `s2 = 1882` при соседях 1718/1396 — нефизичный скачок.
- **Один кадр на точку** (без усреднения, в отличие от `CALIB_HOLD` в
  калибровке): шум кадра ~0.02–0.05° зашит в данные.
- **Ось y систематически шумнее x:** остаточный пол ~0.13° против 0.04–0.08° по
  x, и от степени/чистки почти не падает → это шум y-данных, а не модель.

Отбраковка `3·MAD` (deg3) ловит выбросы автоматически: по x — `i17, i29, i33,
i60`; по y — `i28, i60`. После их удаления данные консистентны.

**Вердикт:** консистентности хватает для полезной компенсации degree 2–3 при
обязательной отбраковке выбросов; **не** хватает, чтобы доверять <0.1° по оси y
или строить degree 4.

## 12.4. Вопрос 3 — достаточно ли точек

Да, с запасом. 100 точек:

- deg2 (6 коэф) — запас ×16, deg3 (10) — ×10, deg4 (15) — ×6.7;
- покрытие 2-D хорошее (98/100 в зоне ±2°, 52 точки вне осей) — не вырожденный
  случай из §11.2.

Ограничивает точность **не число точек**, а (а) шум одного кадра и (б) качество
меток угла. Добавление точек не опустит y-потолок ≈0.13°. Опустит его **усреднение
кадров** после «w» (механика `CALIB_HOLD` уже есть в `run_calibration`) — это
главная рекомендация по съёмке, важнее количества точек.

## 12.5. Вопрос 4 — проверка компенсации на MEASURE.json

Да, проверено тремя независимыми способами:

1. **Leave-one-out** (точная hat-матрица) — таблица §12.2.
2. **Hold-out 70/30**, 200 случайных разбиений, deg3:
   `RMSE_x = 0.083 ± 0.027°`, `RMSE_y = 0.137 ± 0.016°`.
3. **Базовая нож-модель** (`w = 4.064 мм` из `CALIBRATE.json`, та же формула
   `θ = atan(w·erfinv(D)/(√2·FOC))`) на тех же 100 точках:
   `RMSE_x = 0.176°`, `RMSE_y = 0.209°`.

**Итог сравнения:**

| | нож-модель | полином (hold-out) | полином по x, чистые данные |
|---|---|---|---|
| RMSE_x | 0.176° | 0.083° | **0.039°** |
| RMSE_y | 0.209° | 0.137° | 0.126° |

Полином снижает ошибку **примерно вдвое** (по x на очищенных данных — вчетверо).

**Важная находка про шкалу.** Эмпирический наклон
`angle_x_stage ≈ 0.917·θ_knife + 0.076` — близок к **1**, не к 0.5. Значит
**фактора зеркала нет** (`CALIB_ANGLE_SCALE = 1` подтверждается данными), а главный
выигрыш полинома — это снятие ~8 % масштабной ошибки и смещения 0.076° нож-модели
(их ловит уже линейный фит: `LOO_x(deg1)=0.099 < 0.176` нож-модели). Кривизну
erf-модели полином дочищает старшими членами.

**Оговорка к проверке.** Это in-sample проверка — один стенд, один день, одна
мощность. Она доказывает, что полином снимает **систематику модели**, но не
проверяет дрейф во времени/температуре. Для полностью независимой проверки:
отложить повторные точки (центр-триплет, пара 0.5/1.0) как тест либо снять свежий
`MEASURE.json` и прогнать на нём уже обученный полином.

## 12.6. Рекомендации к реализации (уточнения к §11.3)

- Офлайн-скрипт как в §11.3 (`src/pipeline/poly_calib.py` → `POLY_CALIB.json`), но:
  - **степень по умолчанию 2**, максимум 3 по x; выбор — по LOO RMSE;
  - можно ограничиться парой **1-D полиномов** `θx(ux)`, `θy(uy)` — перекрёстные
    члены на этих данных бесполезны;
  - **обязательный шаг отбраковки** `3·MAD` с печатью ключа (поймает `i17, i28,
    i29, i33, i60`) + ручная проверка дублей (центр-триплет и пара `i54/i60`).
- **Доработать `measure`:** усреднять `CALIB_HOLD` кадров после «w» вместо одного
  кадра — главный способ опустить y-потолок 0.13°.
- **Зафиксировать шкалу:** данные сняты в **углах столика**, рантайм должен
  показывать ту же шкалу (фактор зеркала = 1; `CALIB_ANGLE_SCALE` уже убран).
- **`d_max` в рантайме** можно поднять до ~0.85 (данные доходят до 0.81 без
  насыщения), но экстраполяцию за обучающую зону по-прежнему запрещать (§11.4).
- В `POLY_CALIB.json` писать паспортную точность из LOO (ожидаемо ~0.05° по x,
  ~0.13° по y на текущих данных).
