# Задача №9: калибровочный полином по данным measure — анализ

Исходные данные (TASK.md, Задача №9): режимом `cli.py measure` по всей плоскости
датчика снимается 30–50 точек; каждая точка в `DATA/MEASURE/MEASURE.json` — это
сырые значения квадрантов `s = [s1..s4]` (один кадр на нажатие «w») и истинные
углы поворотного столика `angle_x`, `angle_y` (ввод с терминала).

Вопросы: (1) можно ли по этим данным построить полином, корректирующий
измеренные углы; (2) алгоритм получения полинома и его коэффициентов.

## 11.0. Краткий вывод

**Да, можно — но только внутри зоны измерения** (|D| ≲ 0.9–0.95, т.е. ±1–3° по
анализу §8.1). Полином исправляет *систематические* ошибки текущей нож-модели
(зазор между квадрантами, неравномерность чувствительности квадрантов,
негауссовость пятна, неточность w, зеркальный масштаб `CALIB_ANGLE_SCALE`,
поворот осей столика относительно осей датчика). Полином **не может** вернуть
информацию, потерянную в зоне насыщения (|D| → 1 — сигнал перестаёт меняться,
никакая функция от него угол не восстановит) и не убирает шум одиночного кадра.

Рекомендуемая модель: полином **полной степени 3 от двух переменных** в
erfinv-пространстве `u = erfinv(D)` — 10 коэффициентов на ось; 30–50 точек для
этого достаточно (запас ×3–5). Степень выбирать кросс-валидацией
(leave-one-out), а не на глаз.

Критическое условие: точки должны покрывать плоскость **двумерно** (сетка, а не
только оси x/y). Если стенд реально качает луч только по x (как в калибровке
Задачи №4), перекрёстные члены полинома неопределимы — получится только
одномерный полином θx(Dx), что тоже полезно, но не «по всей плоскости».

## 11.1. Что содержит входной файл и как из него получить (D, θ)

Из `s1..s4` каждой точки считаются те же величины, что в пайплайне (формулы
обязаны совпадать с `make_point` / `measure._read_point`, включая раскладку
ph↔s — см. CLAUDE.md «Sensor layout convention»):

    b_i = max(0, ADC_MAX − s_i),  P = Σ b_i
    Dx = (b4 + b3 − b1 − b2) / P    # право − лево
    Dy = (b1 + b4 − b2 − b3) / P    # верх − низ

Истинные углы — `angle_x`, `angle_y` столика. Полином, обученный на углах
столика, **автоматически поглощает** зеркальный множитель
(`CALIB_ANGLE_SCALE`): если дисплей должен показывать оптический угол, его надо
либо учесть при подготовке данных (θ_opt = SCALE·θ_stage), либо договориться,
что рантайм всюду показывает углы столика. Это решение нужно зафиксировать ДО
фита, иначе полином и нож-модель будут в разных шкалах.

Чего во входных данных нет и что ограничивает точность:

- **Один кадр на точку** (без усреднения, в отличие от `CALIB_HOLD` в
  калибровке) — весь шум кадра уходит в данные. Лечится либо доработкой
  `measure` (усреднять N кадров после «w», как в `run_calibration`), либо
  числом точек: полином по 30–50 точкам сам усредняет шум.
- **Нет признака достоверности** — фильтровать точки придётся постфактум
  (см. §11.3, шаг 2).

## 11.2. Можно ли построить полином (ответ на вопрос 1)

Отображение (θx, θy) → (Dx, Dy) для квадрантного датчика гладкое и монотонное в
центральной зоне, значит обратное отображение существует и приближается
полиномом — это стандартная линеаризация квадрантного детектора. Условия:

1. **Зона валидности.** Только |D| ≤ d_max ≈ 0.95. При |D| → 1 производная
   dD/dθ → 0 (насыщение erf, §8.1) — обратная функция имеет вертикальную
   асимптоту, полином её не приблизит, а точки из этой зоны испортят фит во
   всей области. Точки с |Dx| или |Dy| > d_max из обучения исключать; в
   рантайме за пределами d_max полином не применять (там работает логика
   Задачи №8: насыщение / потеря позиции).

2. **Двумерное покрытие.** Чтобы определить перекрёстные члены (связь Dx с θy:
   поворот осей, асимметрия пятна), нужны точки вне осей — сетка ≈ 6×7 по
   рабочей зоне (≈ 40 точек) идеальна. Точки только вдоль осей дают вырожденную
   матрицу плана для членов `Dx·Dy` и старше.

3. **Число точек против числа коэффициентов.** Полный двумерный полином
   степени n имеет (n+1)(n+2)/2 коэффициентов на ось:

   | степень n | коэф./ось | минимум точек (×3 запас) | 30–50 точек |
   |-----------|-----------|--------------------------|-------------|
   | 1         | 3         | 9                        | с большим запасом |
   | 2         | 6         | 18                       | да          |
   | 3         | 10        | 30                       | да (рекомендуется) |
   | 4         | 15        | 45                       | на пределе  |
   | 5         | 21        | 63                       | нет         |

   30–50 точек ⇒ рабочая степень 2–3, степень 4 только при ~50 хорошо
   распределённых точках. Выше — гарантированный оверфит (полином начнёт
   воспроизводить шум одиночных кадров).

4. **Базис.** Лучше фитить не от (Dx, Dy), а от `u = erfinv(clip(D, ±d_max))`:
   нож-модель говорит, что θ ≈ atan(w·u/(√2·FOC)) — почти **линейна по u**.
   Тогда полином степени 1–2 уже ловит основную зависимость, а старшие члены
   описывают только остаточную систематику; в D-базисе ту же кривизну пришлось
   бы выбирать степенью 5+. Обе переменные (u_x, u_y) ограничены и одного
   масштаба — матрица плана хорошо обусловлена без дополнительной нормировки.

Что полином исправит: зазор между квадрантами, разброс чувствительности s1..s4,
негауссовость/эллиптичность пятна, ошибку w из калибровки, масштаб зеркала,
малый поворот осей. Что не исправит: шум, насыщение, дрейф во времени и по
температуре (полином снят в один день при одной мощности — при смене условий
калибровку повторять).

## 11.3. Алгоритм получения коэффициентов (ответ на вопрос 2)

Оформляется как офлайн-скрипт (предлагаемое место —
`src/pipeline/poly_calib.py`, вызов `python cli.py polyfit` или вручную);
вход `DATA/MEASURE/MEASURE.json`, выход `DATA/MEASURE/POLY_CALIB.json`.

**Шаг 1 — подготовка.** Для каждой точки i: b, P, Dx, Dy по формулам §11.1;
θx_i, θy_i — углы столика (при необходимости × `CALIB_ANGLE_SCALE`).

**Шаг 2 — фильтрация.** Отбросить (с печатью причины): P ≤ 0 или ниже порога
слабого сигнала (аналог `CALIB_MIN_FRAC`); |Dx| > d_max или |Dy| > d_max;
число засвеченных квадрантов nz < `NZ_ANGLE_MIN` (по `quadrant_fracs`, как в
Задаче №8). Если после фильтра осталось < 3·(число коэффициентов) точек —
понизить степень.

**Шаг 3 — базис и матрица плана.** u_x = erfinv(Dx), u_y = erfinv(Dy);
мономы полной степени ≤ n: V[i, k] = u_x^p · u_y^q, p+q ≤ n.

**Шаг 4 — МНК отдельно по осям.**

    c_x = argmin ‖V·c − θx‖²,   c_y = argmin ‖V·c − θy‖²   (np.linalg.lstsq)

**Шаг 5 — выбор степени кросс-валидацией.** Для n = 1..4 посчитать
leave-one-out RMSE (при 30–50 точках честный цикл «выкинуть точку — пофитить —
предсказать» стоит копейки; либо через диагональ hat-матрицы:
r_loo = r_i/(1−h_ii)). Взять n с минимальным LOO RMSE — обычно это 2 или 3.
Обучающий RMSE падает с n всегда, ориентироваться на него нельзя.

**Шаг 6 — выбросы.** Точки с |остатком| > 3·MAD печатать с ключом (i7, …) —
почти наверняка опечатка при вводе угла в терминале — и перефитить без них.

**Шаг 7 — сохранение.** JSON в духе CALIBRATE.json:

```json
{
  "created": "20260610_HHMMSS",
  "source": "DATA/MEASURE/MEASURE.json",
  "basis": "erfinv",
  "angle_space": "stage",
  "degree": 3,
  "d_max": 0.95,
  "coef_x": [c00, c10, c01, c20, c11, c02, ...],
  "coef_y": [...],
  "n_points": 42,
  "rmse_deg":     {"x": 0.012, "y": 0.015},
  "loo_rmse_deg": {"x": 0.018, "y": 0.022},
  "warnings": ["точки только вдоль оси x — перекрёстные члены обнулены", ...]
}
```

LOO RMSE в файле — это и есть паспортная точность калибровки: ожидаемая ошибка
угла на новой точке.

Эскиз ядра (numpy/scipy уже в зависимостях):

```python
def _design(ux, uy, deg):
    cols = [ux**p * uy**q for p in range(deg + 1)
                          for q in range(deg + 1 - p)]
    return np.column_stack(cols)

V = _design(erfinv(dx), erfinv(dy), deg)          # dx, dy уже клипнуты ±d_max
cx, *_ = np.linalg.lstsq(V, theta_x, rcond=None)
cy, *_ = np.linalg.lstsq(V, theta_y, rcond=None)
```

Вырожденный случай «стенд качает только x»: автоматически детектируется по
разбросу θy (если std(θy) ≈ 0 — перекрёстные и y-члены не фитить, в файл писать
warning, полином применять только к θx).

## 11.4. Применение полинома в рантайме

Точка интеграции одна — `make_point`, там же, где сейчас вызывается
`deflection_angles` (углы из x_norm/y_norm уже посчитаны):

1. При старте `log`/`stream` загрузить `POLY_CALIB.json` (по аналогии с
   `_calib_radius` → `spot_radius_from_calib`); нет файла — работает текущая
   нож-модель, поведение не меняется.
2. Если |x_norm| ≤ d_max и |y_norm| ≤ d_max — углы из полинома:
   θ = Σ c_pq · erfinv(x_norm)^p · erfinv(y_norm)^q (обе оси считаются от
   обеих переменных — в этом и смысл перекрёстных членов).
3. Вне d_max полином **экстраполировать нельзя** (полиномы за пределами
   обучающей области расходятся) — отдавать нож-модель с признаком
   «ненадёжно» либо состояние насыщения/потери из Задачи №8.
4. Ветки `no_signal` / `lost` не трогаются — полином работает только там, где
   сейчас выдаются числа углов.

## 11.5. Рекомендации по съёмке данных (чтобы полином получился)

- Сетка по рабочей зоне (±1–3° по §8.1, а не по всему датчику ±8°): например
  7 положений по x × 6 по y = 42 точки; обязательно включить точку (0, 0) и
  углы зоны. Точки за пределами зоны измерения снимать бессмысленно — они
  отфильтруются.
- Несколько точек снять дважды (повторы в разное время) — разница повторов
  сразу даёт оценку шума одного кадра и потолок точности полинома.
- Желательная доработка `measure`: усреднять `CALIB_HOLD` кадров после «w»
  вместо одного кадра (механика уже есть в `run_calibration`) — снизит шум
  данных в разы при том же числе точек.
- Не трогать мощность лазера и фокусировку между точками: D — отношение, к
  общей мощности он устойчив, но форма пятна должна оставаться той же.
