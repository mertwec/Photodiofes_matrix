# Задача №10: алгоритмы проекта простым языком

Документ описывает три основных алгоритма проекта так, чтобы их понял человек,
не читавший код:

1. [вычисление диаметра пятна](#1-диаметр-пятна);
2. [вычисление угла поворота (отклонения луча)](#2-угол-отклонения-луча);
3. [вычисление точки на экране](#3-точка-на-экране).

Дополнительно §6 даёт теоретическое описание определения направления при потере
позиции — без привязки к координатам дисплея.

Все три опираются на одни и те же входные данные и одни и те же соглашения,
поэтому сначала — общая часть (§0), без неё формулы ниже не читаются.

Где это в коде:
- `src/pipeline/get_single_point.py` — точка на экране и угол (`make_point`,
  `light_direction_to_point`, `deflection_angles`);
- `src/pipeline/calib_radius.py` — диаметр пятна из калибровки;
- `config.py` — все числовые параметры (`cfg.*`).

## 0. Общая часть: что приходит с датчика и как мы это читаем

### 0.1. Что физически измеряется

Датчик — это квадрат 14 мм (`cfg.DET_SIZE_MM`), разбитый на 4 квадранта
(2×2). На него падает отражённый лазерный луч (λ = 1.064 мкм). Оптика формирует
на датчике расфокусированное пятно диаметром ~6–9 мм (датчик стоит не в фокусе —
см. §2.5). Каждый квадрант выдаёт одно число — **сколько энергии луча в него
попало**.

Важно: это именно энергия, а не «какая площадь квадранта перекрыта пятном».
Чем больше энергии — тем «ярче» квадрант для нас.

### 0.2. Сырое число «наоборот» — инверсия в яркость

С АЦП приходит сырое значение, и оно перевёрнуто относительно интуиции:

- сырое `0` — квадрант засвечен максимально (много света);
- сырое `~3500` — квадранта почти не касается свет (`cfg.ADC_MAX`);
- сырое `4096` (один шаг за пределами 12-битного диапазона `0..4095`) —
  служебное значение «сигнала нет», устройство шлёт его сразу по всем
  четырём квадрантам.

Чтобы работать с привычной «яркостью» (больше число = больше света),
каждое сырое значение переворачивают:

```
яркость b_i = max(0, ADC_MAX − сырое_i)
```

`max(0, …)` (клиппинг нулём) — обязателен: служебное `4096` больше `ADC_MAX`,
без клиппинга яркость стала бы отрицательной и испортила бы расчёт направления.

### 0.3. Раскладка квадрантов (модель = физический датчик)

Модель пронумерована так, чтобы **напрямую повторять физическое расположение
датчиков** - индекс модели совпадает с индексом канала (`ph_i = s_i`):

```
датчик (CSV/UART):
ph1 | ph4  
ph2 | ph3        
```

То есть `ph1=s1`, `ph2=s2`, `ph3=s3`, `ph4=s4`. Отсюда геометрия:

- верхняя строка — `s1, s4`; нижняя строка — `s2, s3`;
- левый столбец — `s1, s2`; правый столбец — `s4, s3`.

Из яркостей собирается матрица 2×2 в этом же физическом порядке (строки сверху
вниз, столбцы слева направо):

```
matrix = [[b1, b4],     ←  верх:  s1 | s4
          [b2, b3]]      ←  низ:   s2 | s3
```

Важно сохранять именно этот порядок строк/столбцов при сборке матрицы — он
задаёт, где «право/лево» и «верх/низ». Те же формулы направления продублированы
в `src/measure.py` и `src/calibration.py`; при изменении раскладки менять надо во
всех трёх местах.

### 0.4. Два разностных сигнала — основа всего

Из четырёх яркостей считаем сумму и две нормированные разности:

```
S      = b1 + b2 + b3 + b4              (полная энергия на датчике)
x_norm = (b4 + b3 − b1 − b2) / S        право − лево,  диапазон [−1, +1]
y_norm = (b1 + b4 − b2 − b3) / S        верх − низ,    диапазон [−1, +1]
```

- `x_norm` > 0 — луч смещён вправо, < 0 — влево.
- `y_norm` > 0 — вверх, < 0 — вниз.

Деление на `S` делает сигнал **независимым от яркости луча**: если луч стал
ярче в два раза, все `b_i` вырастут в два раза, а отношение не изменится.
Поэтому неважно, какой именно масштаб у `ADC_MAX` (для лога — реальный максимум
по файлу, для живого потока — `cfg.ADC_MAX`): в `x_norm`/`y_norm` он сокращается.

Эти `x_norm`, `y_norm` — то, что в нож-модели обозначается буквой **D**
(difference, разностный сигнал). Через них считаются и точка, и угол.
`D = x_norm`

## 1. Диаметр пятна

### 1.1. Главная мысль

Диаметр (точнее — радиус `w` по уровню 1/e²) пятна, это физическое свойство оптики, оно постоянно.
Его определяют один раз — калибровкой нож-сканированием (Задача №4 → файл `DATA/CALIB/CALIBRATE.json`) —
и потом подставляют как константу `fixed_radius` во все кадры с сигналом.

Если файла калибровки нет — радиус не известен, кружок пятна **не рисуется**
вовсе, и углы тоже не считаются (для них нужен `w`).

### 1.2. Откуда берутся калибровочные точки

Луч сканируют поперёк границы квадрантов поворотным столиком и фиксируют
три положения (углы столика в градусах):

- `i0` — луч в центре (опора нуля угла);
- `i1` — крайнее правое;
- `i2` — крайнее левое.

**По какому критерию определяется положение** (`src/calibration.py::_pos_ok`).
Решает разностный сигнал `D = x_norm` (право−лево, §0.4). Во
всех случаях должен присутствовать луч: максимальная доля засветки квадранта
`sig ≥ cfg.CALIB_MIN_FRAC` (= 0.10), иначе положение не засчитывается. Условия:

- `i0` (центр): `|x_norm| < cfg.CALIB_CENTER_EPS` **и** `|y_norm| < cfg.CALIB_CENTER_EPS`
  (= 0.08) — энергия распределена почти поровну между всеми квадрантами;
- `i1` (крайнее правое): `x_norm > +cfg.CALIB_SIDE_EPS` (= +0.45) — энергия
  заметно ушла в правый столбец (`s4, s3`);
- `i2` (крайнее левое): `x_norm < −cfg.CALIB_SIDE_EPS` (= −0.45) — энергия
  заметно ушла в левый столбец (`s1, s2`).

Итого «право» и «лево» различаются **знаком** `D`: `D > 0` — луч ушёл вправо
(правые квадранты ярче), `D < 0` — влево. Порог `0.45` — компромисс: точка уже
далеко от центра (большое плечо `x_i` → устойчивая оценка `w`), но ещё далеко от
насыщения `|D| → 1`. Зелёная подсветка точки в окне — лишь подсказка оператору;
фактическая фиксация происходит по клавише «w» (усредняются `cfg.CALIB_HOLD`
кадров), а не автоматически по достижению порога (иначе точку сняло бы во время
вращения столика).

Для каждой точки сохраняются усреднённые `s1..s4`, разностный сигнал
`D = x_norm` и угол столика `angle`. Столик ходит только по оси x, поэтому
боковых точек ровно две.

### 1.3. Нож-модель: как D связан с положением и радиусом

Если пятно гауссово, то при сдвиге его центра на расстояние `s` от границы
квадрантов разностный сигнал ведёт себя по закону «ножа» (функция ошибок):

```
D = erf(√2 · s / w)
```

`erf` — насыщающаяся S-образная функция: при больших `s` сигнал `D` упирается
в ±1. Обратив её, получаем положение центра:

```
s = w · erfinv(D) / √2
```

`erfinv` — обратная функция ошибок.

### 1.4. Как из этого достаём w (ключевой трюк — разности)

Радиус считают **разностью в пространстве аргумента `erfinv`**, а не вычитанием
самих `D`. Для двух точек `i` и `j`:

```
erfinv(D_i) − erfinv(D_j) = √2 · (x_i − x_j) / w
                              ⇓
w = √2 · (x_i − x_j) / (erfinv(D_i) − erfinv(D_j))
```

где `x_i` — линейное смещение центра пятна, пересчитанное из угла столика:

```
x_i = FOC · tan(Δθ_i),   Δθ_i = θ_i − θ_{i0}
```

`FOC` (`cfg.FOC = 50` мм) — расстояние от линзы до матрицы датчиков (это НЕ
фокусное расстояние, см. §2.5), `Δθ_i` — угол точки относительно центра `i0`.

**Почему именно разность.** Луч в `i0` может стоять не точно на границе
квадрантов — есть неизвестное смещение нуля. Когда мы берём разность двух
точек, это смещение сокращается **точно**. Если бы мы вычитали сами `D`,
нелинейность `erf` исказила бы результат.

- Основная оценка `w` — по паре крайних точек `(i1, i2)`: там нуль
  сокращается идеально.
- Центр `i0` используется как контроль: по нему считают диагностический `w`
  каждой боковой точки. Если оценки сильно расходятся — значит асимметрия
  или фоновая засветка (выдаётся предупреждение).

### 1.5. Защита от плохих данных (предупреждения)

`spot_radius_from_points` отбрасывает/помечает точки:

- `|D| ≥ 0.999` — насыщение: `erfinv` уходит в бесконечность, точка непригодна;
- слишком близкие `erfinv(D)` (`< 1e-2`) — деление неустойчиво, пара отброшена;
- знак `D` не согласован со знаком `Δθ` — подозрение на ошибку в перестановке
  ph↔s или в знаке столика;
- разброс оценок `w` > 20 % — несимметричные точки или фон;
- смещённый центр `|D(i0)| > 0.1` — луч в `i0` заметно не на границе.

Все предупреждения печатаются при старте `log`/`stream`.

### 1.6. Перевод в пиксели

Радиус в миллиметрах переводят в пиксели дисплея так, что весь активный размер
датчика занимает весь экран:

```
radius_px = w_mm · cfg.CALIB_PX_PER_MM,   CALIB_PX_PER_MM = SIZE_DISPLAY / DET_SIZE_MM
```

(`SIZE_DISPLAY = 140` px, `DET_SIZE_MM = 14` мм → 10 px/мм.) Этот `radius_px`
и есть тот жёлтый кружок на экране.

## 2. Угол отклонения луча

### 2.1. Что считаем

По двум осям независимо считаем угол отклонения центра луча от оптической оси —
`angle_x` и `angle_y` (в градусах, показаны слева вверху). Это и есть «угол
поворота» из задачи. Нужны радиус пятна `w` (из §1) и расстояние линза→датчик
`FOC`, поэтому без калибровки углы не считаются.

### 2.2. Формула (та же нож-модель)

Берём разностный сигнал по оси (`x_norm` для x, `y_norm` для y), обращаем
нож-модель в смещение центра и переводим смещение в угол:

```
шаг 1:  d = w · erfinv(D) / √2          смещение центра пятна, мм
шаг 2:  θ = atan(d / FOC)               угол отклонения, рад → градусы
```

- `D` — это `x_norm` или `y_norm` (право−лево / верх−низ);
- `w_mm` берётся из постоянного радиуса: `w_mm = radius_px · DET_SIZE_MM / size`
  (обратный перевод пикселей в мм);
- `FOC = 50` мм — расстояние от линзы до матрицы датчиков (НЕ фокусное
  расстояние; см. §2.5).

Перед `erfinv` сигнал `D` ограничивают диапазоном `±0.999` (`_D_CLIP`), иначе
у ±1 функция уходит в бесконечность.

### 2.3. Простыми словами

«Насколько сильно перекос энергии между половинами датчика» (`D`) → «насколько
сместился центр пятна на датчике» (`d`, через нож-модель) → «под каким углом
луч пришёл», зная расстояние от линзы до датчика `FOC` (`θ = atan(d / FOC)`).

Формально угол зависит и от `FOC`, и от размера пятна `w`. Но `w` мы получаем из
той же калибровки, где `FOC` тоже участвует, поэтому в итоговом угле `FOC` почти
полностью сокращается — подробный разбор и влияние погрешности ±2 мм в §2.5.

### 2.4. Граница применимости (потеря позиции, Задача №8)

Датчик — фактически нуль-индикатор. Точный угол он даёт только пока пятно
задевает почти все квадранты (окно ≈ ±1–3°). Как только энергия ушла в
1–2 квадранта, угол измерить нельзя. Логика:

- для каждого квадранта считается **доля засветки** `b_i` (`quadrant_fracs`):

  ```
  b_i = clip( (S_VAL_MIN − raw_i) / (S_VAL_MIN − S_VAL_MAX),  0, 1 )
  ```

  Это безразмерная величина в диапазоне `[0, 1]` (доля от полной шкалы
  квадранта): `b_i = 1` при `raw_i = S_VAL_MAX` (≈ 40, квадрант засвечен
  полностью), `b_i = 0` при `raw_i = S_VAL_MIN` (≈ 3350, света нет);
- квадрант считается «засвеченным», если `b_i > cfg.FRAC_EPS`; число таких
  квадрантов — `nz`;
- если `nz < cfg.NZ_ANGLE_MIN` (3) — кадр помечается `lost=True`: вместо углов
  прочерк `θx= —  θy= —`, кружок не рисуется, точка уезжает на край экрана
  (см. §3.3).

**Подробнее про порог `FRAC_EPS = 0.01`.** Единицы — это **доля засветки** (та
самая `b_i`): безразмерная величина `[0, 1]`, а не сырые отсчёты АЦП и не вольты.
`0.01` означает «квадрант засчитывается засвеченным, если в нём есть хотя бы 1 %
от полной засветки». В сырых отсчётах это очень низкий порог: `b_i = 0.01`
соответствует

```
raw_порог = S_VAL_MIN − 0.01·(S_VAL_MIN − S_VAL_MAX) = 3350 − 0.01·3310 ≈ 3317,
```

то есть квадрант считается «живым» при любом заметном превышении над уровнем
«нет сигнала» (≈ 3350). Порог намеренно мал: его задача — отсечь только
шум/полное отсутствие сигнала, а не отделять «много» света от «мало». Само
решение о потере позиции принимает не величина порога, а **число** засвеченных
квадрантов `nz` относительно `NZ_ANGLE_MIN`. Поэтому точное значение `FRAC_EPS`
не критично — годится любое маленькое (0.005…0.03); важно лишь, чтобы оно было
выше шума АЦП и ниже доли реально освещённого квадранта.

### 2.5. Что такое `FOC` и как влияет его погрешность ±2 мм

`FOC` (= 50 мм) — это **не фокусное расстояние оптики**, а расстояние от линзы
до плоскости матрицы датчиков. Датчик стоит в расфокусе: фокус оптики находится
примерно на 17 мм ближе линзы (`cfg.DEFOCUS_MM`), поэтому на датчик попадает
слегка расфокусированный кружок, а не точка. Само значение `FOC` известно с
погрешностью **±2 мм** (≈ ±4 % от 50 мм).

`θ = atan(d / FOC)`. 

**Как ±2 мм влияет — по двум выходам по отдельности:**

1. **Угол отклонения θ — практически НЕ зависит от `FOC`.** Радиус `w` берётся из
   калибровки, где `w = √2·(x_i − x_j)/Δerfinv`, а `x_i = FOC·tan(Δθ_i)` — то
   есть `w ∝ FOC`. В формуле угла `d = w·erfinv(D)/√2 ∝ FOC`, а затем
   `θ = atan(d / FOC)` — множитель `FOC` в числителе и знаменателе
   **сокращается точно**:

   ```
   θ = atan( (tanΔθ_i − tanΔθ_j)/(erfinv(D_i) − erfinv(D_j)) · erfinv(D) )
       ↑ FOC и √2 ушли — остаются только калибровочные углы столика и сигнал D
   ```

   Это работает, потому что **одно и то же** значение `FOC` используется и в
   калибровке, и в измерении. Значит ошибка `FOC` ±2 мм на измеренный угол
   фактически не влияет (по сути угол — это интерполяция между известными углами
   столика `Δθ_i`).

2. **Размер пятна `w` (жёлтый кружок) — зависит линейно.** Так как `w ∝ FOC`,
   ошибка ±2 мм даёт ±4 % в оценке `w_mm` и, соответственно, ±4 % в радиусе
   нарисованной окружности. Это чисто визуальный эффект; на угол он, как показано
   выше, не переносится.

**Вывод.** Погрешность `FOC` ±2 мм безопасна для главного результата (угла): он
самокалибруется, потому что `FOC` входит и в калибровку, и в измерение и при
делении сокращается. Заметна она лишь как ±4 % в **отображаемом размере пятна**.
Оговорка: сокращение действует, только пока `w` берётся из калибровки с тем же
`FOC`. Если бы `w` задавался независимо (например, из оптического расчёта,
Задача №6), то ±2 мм давали бы ±4 % уже прямо в угле.

## 3. Точка на экране

### 3.1. Нормальный кадр (есть сигнал)

Точка — это просто визуализация направления `(x_norm, y_norm)` (§0.4),
растянутого на половину экрана:

```
X = x_norm · size / 2
Y = y_norm · size / 2
```

`size` = `cfg.SIZE_DISPLAY` (140 px), деление на 2 — потому что центр экрана
это (0,0), а оси идут в обе стороны от −size/2 до +size/2. Чем сильнее перекос
энергии, тем дальше точка от центра в соответствующую сторону.

Вокруг точки рисуется жёлтый кружок радиусом из §1 (если есть калибровка).

### 3.2. Нет сигнала (все квадранты тёмные)

Если суммарная яркость `S ≤ 0` (все датчики прислали `4096` — «сигнала нет»),
точка ставится строго в центр `(0, 0)` и рисуется **красной, без кружка**.
Это и есть визуальный признак «сигнала нет». Специально не отдаём `point=None`,
чтобы поведение было предсказуемым.

### 3.3. Потеря позиции: как определяется направление (Задача №8)

Когда энергия ушла в 1–2 квадранта (`nz < cfg.NZ_ANGLE_MIN`, см. §2.4), точный
угол не измерить, но **направление, куда ушёл луч, всё ещё нужно** — это сигнал
оператору/контуру управления, в какую сторону возвращать пятно. Алгоритм в
`make_point` состоит из четырёх шагов.

**Шаг 1. Память направления `last_dir`.** В каждом достоверном кадре (есть сигнал
и `nz ≥ NZ_ANGLE_MIN`) запоминается направление `last_dir = (x_norm, y_norm)`.
Это последнее измерение, сделанное ещё в надёжной зоне — у самой границы ухода.

**Шаг 2. Выбор направления в кадре потери.** Когда наступила потеря позиции,
берётся:

```
dx, dy = x_norm, y_norm                 # направление текущего (потерянного) кадра
если last_dir задан и не нулевой:
    dx, dy = last_dir                   # приоритет — последнему надёжному
```

Почему приоритет у `last_dir`, а не у текущего `x_norm/y_norm`: при энергии в
1–2 квадрантах текущая разность уже **в насыщении** (`|D| → 1`) и показывает лишь
грубый знак, а не направление; последнее же измерение в линейной зоне — самое
точное указание стороны ухода. Текущий кадр используется только как запасной
вариант, когда истории ещё нет (потеря с самого первого кадра).

**Шаг 3. Проекция на край экрана (норма Чебышёва).** Направление `(dx, dy)`
вытягивается до границы квадратного дисплея:

```
m = max(|dx|, |dy|)
точка = ( dx/m · size/2,  dy/m · size/2 )     ← садится на сторону квадрата
```

Деление на `m = max(|dx|, |dy|)` (а **не** на длину вектора) делает большую по
модулю координату равной `±size/2` — точка ложится ровно на сторону квадрата
экрана (а не на вписанную окружность), сохраняя направление. Так по краю видно,
в какой стороне (или в каком углу) исчез луч.

**Шаг 4. Устойчивость к миганию.** `last_dir` обновляется только в достоверных
кадрах и **переживает** промежуточные кадры «нет сигнала» (§3.2 их не трогает) —
поэтому при кратковременном пропадании луча стрелка не прыгает в центр, а
продолжает указывать последнюю известную сторону, пока сигнал не вернётся.

Точка потери рисуется **жёлтой** — это отличает её от красной «нет сигнала» в
центре и от обычной точки направления. Теоретическое обоснование, не привязанное
к пикселям дисплея, — в §6.

### 3.4. Сводка по цвету точки

| Состояние        | Где точка             | Цвет     | Кружок | Углы      |
|------------------|-----------------------|----------|--------|-----------|
| Есть сигнал      | по `(x_norm, y_norm)` | обычный  | да*    | да*       |
| Нет сигнала      | центр `(0, 0)`        | красный  | нет    | нет       |
| Потеря позиции   | край экрана           | жёлтый   | нет    | прочерк   |

\* кружок и углы — только если есть калибровка (`fixed_radius`).

## 4. Как три алгоритма связаны (картина целиком)

```
сырые s1..s4  ──► инверсия в яркость b_i  ──► матрица [[b1,b4],[b2,b3]]  (§0)
                                                  │
                       ┌──────────────────────────┼──────────────────────────┐
                       ▼                           ▼                           ▼
                 S, x_norm, y_norm           x_norm, y_norm                S ≤ 0?
                       │                           │                           │
                       ▼                           ▼                           ▼
            ТОЧКА на экране (§3)        УГОЛ θx, θy (§2)              нет сигнала (§3.2)
            X=x_norm·size/2            d=w·erfinv(D)/√2              красная точка в центре
            Y=y_norm·size/2            θ=atan(d/FOC)
                                            ▲
                                            │ нужен радиус w
                                            │
                      ДИАМЕТР ПЯТНА (§1): один раз из калибровки
                      w = √2·(x_i−x_j)/(erfinv(D_i)−erfinv(D_j))
                      x_i = FOC·tan(Δθ_i),  radius_px = w_mm·PX_PER_MM
```

Коротко:
- **Точка** показывает *направление* перекоса энергии — работает всегда,
  даже без калибровки.
- **Диаметр** — единственная величина, которую нельзя достать из кадра; её
  берут из калибровки и держат постоянной.
- **Угол** — это направление (`D`), пересчитанное в физический угол через
  размер пятна (`w`) и расстояние до датчика (`FOC`); поэтому угол есть только
  при наличии калибровки и только пока датчик не «насыщен» (пятно задевает
  ≥3 квадрантов). Важно: ошибка `FOC` в самом угле почти сокращается (§2.5).

## 6. Теория: направление потери позиции без привязки к дисплею

Раздел описывает определение направления ухода луча **абстрактно** — в терминах
энергий квадрантов и нормированного вектора направления, без единиц дисплея
(пикселей, `size`). Пиксельная отрисовка из §3.3 — лишь визуализация этого
вектора.

### 6.1. Вектор направления как энергетический центроид

Сопоставим каждому квадранту единичный вектор к его центру на нормированной
сетке `[−1, +1]²` (центр датчика — начало координат, оси: x вправо, y вверх):

```
s1 (верх-лево)  → (−1, +1)      s4 (верх-право) → (+1, +1)
s2 (низ-лево)   → (−1, −1)      s3 (низ-право)  → (+1, −1)
```

Энергетический центроид (направление, взвешенное яркостями квадрантов):

```
u = ( Σ b_i · ĉ_i ) / Σ b_i
u_x = (b4 + b3 − b1 − b2) / S = x_norm
u_y = (b1 + b4 − b2 − b3) / S = y_norm
```

То есть **`(x_norm, y_norm)` и есть вектор направления `u`** — куда смещена
энергия пятна, в безразмерных координатах датчика. Он не зависит ни от яркости
луча (деление на `S`), ни от дисплея. Свойства:

- `u = (0, 0)` — энергия симметрична, луч в центре;
- каждая компонента в `[−1, +1]`; вектор живёт в квадрате `[−1, 1]²`;
- вся энергия в одном квадранте → `u` = угол квадрата, напр. `(+1, +1)` (s4);
- вся энергия в одном столбце/строке → `u` на середине стороны, напр. `(+1, 0)`.

### 6.2. Три зоны по «уходу» направления

Режим задаёт число засвеченных квадрантов `nz` (или, эквивалентно, насколько
`u` близок к границе квадрата):

| Зона | Признак | Что известно о направлении |
|------|---------|----------------------------|
| Центр (линейная) | `nz = 4`, модуль `u` мал | полный вектор **и величина** угла (нож-модель, §2) |
| Переход | `nz = 3` | направление надёжно, угол — на пределе точности |
| Потеря | `nz ≤ 2` | только **сторона/знак** ухода; величина недостоверна |

В зоне потери `u` упирается в границу квадрата и вырождается в **дискретное
направление** — его задаёт набор квадрантов, ещё держащих энергию:

```
освещены s4 и s3 (правый столбец)   → уход ВПРАВО      sign(u_x) = +
освещены s1 и s2 (левый столбец)    → уход ВЛЕВО       sign(u_x) = −
освещены s1 и s4 (верхняя строка)   → уход ВВЕРХ       sign(u_y) = +
освещены s2 и s3 (нижняя строка)    → уход ВНИЗ        sign(u_y) = −
освещён один квадрант               → уход в его УГОЛ  (sign(u_x), sign(u_y))
```

### 6.3. Оценка направления и закон управления

В абстрактной форме алгоритм возвращает **единичное направление** ухода:

```
û = u / |u|                       (направление «куда ушёл луч»)
вернуть пятно в центр  ⇒  двигать систему в сторону −û
```

- В **линейной зоне** `û` точен и сопровождается измеренным углом — возможно
  пропорциональное управление (величина шага ∝ углу).
- В **зоне потери** надёжен лишь знак `sign(u_x)`, `sign(u_y)` — это режим
  **bang-bang** (релейное управление): «энергия ушла вправо — двигать влево»,
  без знания величины.
- **Память** последнего надёжного `û` (аналог `last_dir`, §3.3) сохраняет
  направление, пока сигнал не вернётся, и переживает кадры полного отсутствия
  сигнала (там `u` не определён, `S = 0`).

Таким образом весь алгоритм потери позиции формулируется без дисплея: вход —
энергии квадрантов `b_i`, выход — направление `û` (или пара знаков) плюс режим
достоверности по `nz`. Пиксельная проекция §3.3 (`· size/2`, норма Чебышёва) —
лишь способ показать `û` на квадратном экране.
